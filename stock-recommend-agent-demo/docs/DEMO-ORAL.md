# AI 股票投研助手 — 口头讲解稿

> 约 3 分钟 · 配合 [DEMO.md](./DEMO.md) 现场演示使用  
> 括号内为操作建议，不必念出声。

---

## 开场（30 秒）

大家好，接下来演示的是一个 **AI 股票投研助手**。

它不是聊天机器人套壳，而是用**同一套投研业务**，对比两种 AI 落地方式：一种是 **Agent 多角色协作**，一种是 **固定流水线 Workflow**。

你可以把它理解成：左边是「会自己分工的研究团队」，右边是「按 SOP 严格执行的自动化产线」。（打开 http://localhost:5177）

---

## 点题：为什么做这个项目（30 秒）

很多团队在做 AI 应用时会纠结：到底用 Agent，还是用工作流？

这个 Demo 的价值就在这里——**同一个场景、同一套数据源、同一个前端**，你可以直观看到两种模式的差异，而不是只看 PPT 里的概念图。

另外强调一点：本项目**仅供技术演示与学习，不构成任何投资建议**。

---

## 演示 Agent 模式（90 秒）

（确认当前在「Agent 投研」Tab）

我先输入一个自然语言问题，比如：「研究 AI 芯片股 NVDA、AMD、TSM，给出推荐排序和风险提示。」（点击发送）

请大家注意三个区域：

第一，**左侧对话区**。Agent 不会一次性甩给你一篇长文，而是先给简短摘要，方便你快速抓住结论。

第二，**活动面板**。这里能看到 Agent 在干什么——有没有做任务规划、调了哪些工具、子 Agent 是否在跑。这就是 Agent 模式和传统黑盒最大的区别：**过程可见**。

第三，**右侧排序和下方研报**。排序来自规则引擎，每一档推荐都有可解释的分数和情绪标签；研报则是 Markdown 流式输出，像打字机一样实时生成。

（等待结果出来后）可以看到，调研、打分、写报告是分工完成的：有调研员拉行情和新闻，有量化师算分，最后还有编辑审阅。主 Agent 负责统筹，而不是自己包办一切。

---

## 演示追问（30 秒）

Agent 模式的另一个优势是**多轮对话**。

（输入：「前三名各自最大的风险是什么？」）

注意，这时候它**不会重新跑一遍全量调研**，而是基于刚才已经算好的 ranking 直接回答。这既省时间，也更接近真实投研里「先出报告、再答疑」的工作方式。

---

## 对比经典流水线（30 秒）

（切换到「经典流水线」Tab，用同样或类似输入再跑一遍）

大家对比一下：经典模式走的是 LangGraph **固定六步**——解析输入、拉行情、搜新闻、建候选、情绪分析、打分、生成研报。

步骤是确定的，行为可复现，适合对稳定性要求高的场景；但没有 Agent 那种自主规划和子 Agent 委派，也**不支持刚才那种灵活的追问**。

所以这不是谁更好，而是**场景不同、选型不同**。

## 收尾（30 秒）

技术栈方面：Agent 侧用 DeepAgents，流水线用 LangGraph；前端 React，后端 Express，数据来自 Yahoo Finance 和博查新闻搜索。

如果你关心架构细节，可以看同目录下的 AGENT-ARCHITECTURE.md；如果要自己跑一遍，README 里 `npm run dev` 即可。

我的演示到这里。欢迎提问——尤其是关于 Agent 编排、流式展示，以及 Workflow 和 Agent 怎么选型的问题。谢谢。

## 备用一句话（被问到时）

| 问题 | 回答 |
|------|------|
| 和 ChatGPT 直接问股票有什么区别？ | 这里有结构化数据接入、可解释打分和多 Agent 分工，不是纯文本生成。 |
| 刷新页面为什么对话没了？ | 对话在浏览器内存里，刷新会清空；服务端按 session 保存中间结果。 |
